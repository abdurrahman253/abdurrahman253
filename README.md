## 🏗️ How I Think About Architecture

I build in layers. Each layer has one clear job and minimal knowledge of the others.

```
┌─────────────────────────────────────────────────────────────────┐
│                      PRESENTATION LAYER                         │
│    Next.js Pages / App Router  →  React Component Tree          │
│    GSAP ScrollTrigger (scroll)  +  Framer Motion (components)   │
│    Lenis smooth scroll  →  Theme system (next-themes)           │
├─────────────────────────────────────────────────────────────────┤
│                       STATE LAYER                               │
│    TanStack Query  →  all server state, caching, invalidation   │
│    React Hook Form  →  form state + field-level validation      │
│    useState / useRef / Context  →  local and shared UI state    │
├─────────────────────────────────────────────────────────────────┤
│                      SERVICE LAYER                              │
│    Axios instances  →  REST API calls with interceptors         │
│    Firebase SDK  →  auth, real-time database                    │
│    Stripe SDK  →  payment intent creation, webhooks             │
│    EmailJS  →  transactional emails without a mail server       │
├─────────────────────────────────────────────────────────────────┤
│                      BACKEND LAYER                              │
│    Node.js + Express  →  route handlers + middleware pipeline   │
│    JWT verification middleware  →  protects every private route │
│    MongoDB + aggregation pipelines  →  complex data queries     │
│    CORS + dotenv + helmet  →  security baseline                 │
└─────────────────────────────────────────────────────────────────┘
```

**Principles I apply in every project:**

- **No raw `useEffect` for data fetching** — TanStack Query handles all server state
- **GSAP contexts always cleaned up** — `ctx.revert()` on component unmount, zero memory leaks
- **Auth lives in two places** — Firebase guards the client, JWT guards the server; neither alone is enough
- **Animations enhance, never block** — functionality ships first, motion is added as a layer on top
- **Components have one job** — if a component is hard to name, it probably does too much

## 🔧 Engineering Principles I Follow

```
1.  Understand before building  →  never cargo-cult code I don't understand
2.  Server state ≠ client state  →  TanStack Query for one, React state for the other
3.  Cleanup is not optional      →  event listeners, GSAP contexts, subscriptions — always removed
4.  Authentication has two sides →  client sessions + server middleware verification, always both
5.  Responsive is not a feature  →  it's a baseline requirement, designed in from the start
6.  Animations are a layer       →  functionality first, motion second, never the other way
7.  Names matter                 →  a well-named variable is documentation that never goes stale
8.  Ship, then improve           →  deployed > perfect but unfinished
9.  Read the docs                →  AI gives suggestions, official docs give truth
10. Ask why                      →  every pattern I use, I know the reason it exists
```
